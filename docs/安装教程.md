# CastleCraft 完整版安装教程

本教程用于 Windows 上的 Lost Castle／失落城堡第一代与 Minecraft Java 26.3 桥接。它是独立安装包，可以通过 Steam、Minecraft 官方启动器、PCL 或其他 Fabric 启动器手动使用。教程、检测小程序和压缩包均不依赖 Melty。

## 1. 阅读顺序与文件目录

先安装两个正版游戏 → 安装城堡端加载器和桥接 DLL → 安装 Minecraft 26.3/Fabric 和桥接 JAR → 检查 Vulkan → 运行识别程序 → 用户自行启动两个游戏。

| 文件 | 用途 |
| --- | --- |
| CastleCraft安装识别.exe | 自动寻找游戏目录，核对版本和安装文件；不会启动游戏 |
| package-manifest.json | 本包版本、兼容基准及 SHA-256 校验信息，请与 EXE 放在一起 |
| 模组文件/Lost Castle_首次安装包.zip | 包含本机已使用的 BepInEx 5.4.23.5 加载器及两份桥接 DLL |
| 模组文件/Lost Castle_桥接更新包.zip | 只有两份桥接 DLL；适合已装好 BepInEx 的用户 |
| 模组文件/Minecraft_桥接与前置.zip | 桥接 JAR 与配套 Fabric API；Fabric Loader 由启动器安装 |
| 教程/可选模组清单.md | 可选模组的名称与作者提供的来源；额外模组请自行下载 |
| 教程/可选模组清单.md | 每个 JAR 的名称、版本、平台、角色与作者提供的链接 |
| 许可与来源 | 上游许可、下载来源及维护说明 |
| 源码单独下载 | GitHub 仓库和 Sources 压缩包提供完整源码与编译说明 |

这些压缩包没有两个游戏本体、存档、账号、启动器账号配置或显卡驱动。旧的 disabled 插件、错误报告、尚未完成的 Re-Avaritia Fabric 移植也不作为成品放入包中。

## 2. 支持的环境与基本原理

| 项目 | 这份包的基准 |
| --- | --- |
| 操作系统 | Windows 64 位；检测程序使用 .NET Framework 4.8 |
| Lost Castle | 第一代 PC 版；Unity 2021.3.25f1，当前实机为 Direct3D 11 |
| 城堡加载器 | BepInEx 5.4.23.5，Windows x64、Unity Mono |
| Minecraft | Java Edition 26.3；不是基岩版、不是 1.20.1/1.21，也不是“26.3”命名的旧实例 |
| Minecraft 加载器 | Fabric Loader 0.19.5 或更新的兼容版本 |
| Java | 启动器实际使用 64 位 Java 25；不能只改版本 JSON 的数字 |
| 必要前置 | 配套 Fabric API 0.161.0+26.3 |
| 推荐图形 API | Minecraft 原生 Vulkan，支持改回 OpenGL 排查兼容问题 |

桥接运行时需要两个游戏进程同时存在：Minecraft 处理玩家、物品、方块和 Minecraft 实体，城堡保留自己的关卡与原生逻辑。它不是把一个游戏安装进另一个游戏的存档，也不是只打开城堡即可运行的单进程版本。

Vulkan → D3D11 共享已经有真实跨进程纹理测试证据。当前共享范围主要是 HUD、菜单与手持画面；世界和实体几何仍有原来的 CPU 通信流程。Vulkan 不代表整个城堡都被改成 Vulkan，也不保证任何电脑都达到固定帧率。

## 3. 安装 Lost Castle 游戏与城堡模组

### 3.1 安装和找到游戏目录

1. 从 [Lost Castle 官方 Steam 商店](https://store.steampowered.com/app/434650/Lost_Castle/)获取并安装第一代游戏。Lost Castle 2 不适用此包。
2. 先正常启动原版一次，确认游戏可以进入菜单，然后正常退出。
3. 在 Steam 库中对游戏打开管理菜单，选择浏览本地文件。得到的目录必须直接包含 Lost_Castle.exe、UnityPlayer.dll 和 Lost_Castle_Data。
4. 安装前正常退出两个游戏。保留已有模组或配置的备份。

正确目标示例：D:\Games\Steam\steamapps\common\Lost Castle。不是 Steam 根目录，也不是 Lost_Castle_Data 里面。

### 3.2 第一次安装

1. 解压“Lost Castle_首次安装包.zip”到刚才的游戏根目录。
2. 合并 BepInEx 文件夹。不要解压成 Lost Castle/Lost Castle_首次安装包/BepInEx 这样的多层目录。
3. 最终应该看到如下结构：

```
Lost Castle/
  Lost_Castle.exe                 ← 原版游戏已有，不在本包中
  UnityPlayer.dll                 ← 原版游戏已有，不在本包中
  Lost_Castle_Data/               ← 原版游戏已有，不在本包中
  winhttp.dll                    ← 加载器入口
  doorstop_config.ini
  BepInEx/
    core/                        ← BepInEx 加载器依赖
    plugins/CastleCraft/
      CastleCraft.Passthrough.dll
      CastleCraft.GpuBridge.dll
```

4. 已有其他 BepInEx 模组时，先备份，不要直接覆盖一个不同大版本的加载器。本包针对 BepInEx 5，不是 BepInEx 6/IL2CPP。
5. 自行启动城堡一次。BepInEx 会生成日志和配置；检查 BepInEx/LogOutput.log 是否有 CastleCraft 插件加载记录。

也可以从 [BepInEx 官方发布页](https://github.com/BepInEx/BepInEx/releases/tag/v5.4.23.5)安装 Windows x64 的对应版本，然后解压“桥接更新包”。加载器原理和安装说明见 [BepInEx 官方文档](https://docs.bepinex.dev/articles/user_guide/installation/index.html)。

### 3.3 已经装好加载器，只更新桥接

1. 正常退出城堡与 Minecraft。
2. 备份 BepInEx/plugins/CastleCraft 中原来的两份 DLL。
3. 解压“Lost Castle_桥接更新包.zip”到游戏根目录，替换这两份 DLL。
4. 保留已有 BepInEx/config/castlecraft.bridge.cfg。不要为了更新删除配置、原生存档或整个 BepInEx。
5. 确认旧桥接 DLL 不再以 .dll 后缀重复加载。可以移到外部备份目录。

### 3.4 加载入口不工作

doorstop_config.ini 的 General 节应有 enabled = true，target_assembly 指向 BepInEx\core\BepInEx.Preloader.dll。winhttp.dll 必须位于游戏 EXE 旁边；winhttp.dll.melty-off、.disabled 或仅存在于备份目录的文件不会作为正确入口工作。

检测程序会检查入口、核心依赖和实际 DLL 哈希。检测成功代表文件与版本基准匹配，不代表两个尚未启动的进程已经建立连接。

## 4. 安装 Minecraft 26.3 与 Fabric 桥接

### 4.1 游戏与 Java

1. 安装 [Minecraft Java Edition 和官方启动器](https://www.minecraft.net/download)。使用自己的游戏账号。
2. 在官方启动器或 PCL 中创建 Minecraft 26.3 实例。推荐为桥接单独建实例，避免影响平时的存档与整合包。
3. 给该实例选择 64 位 Java 25。若启动器管理 Java，检查它最终选用的运行时。
4. 下载基础游戏和依赖，先正常启动一次到标题界面，再正常退出。
5. 为 FFM 原生桥接，在启动器的 Java/JVM 参数项加入 --enable-native-access=ALL-UNNAMED。各启动器的参数项名称不同；它是 JVM 参数，不是游戏命令或聊天指令。

### 4.2 安装 Fabric Loader

官方启动器可以使用 [Fabric 官方安装器](https://fabricmc.net/use/installer/)，选择 Minecraft 26.3、Client、Loader 0.19.5 或兼容更新版。PCL 等启动器也可以在版本安装页面选择 Fabric。

安装 Fabric 后，从对应的 Fabric 实例启动游戏。不要误选旁边同名原版、Forge 或 NeoForge 实例。

### 4.3 先分清两个目录

| 目录 | 负责什么 | 示例 |
| --- | --- | --- |
| 版本目录 | 版本 JSON、继承关系、Fabric 启动入口 | .minecraft/versions/26.3-Fabric |
| 实际游戏目录 | mods、config、options.txt、logs、saves | 启动器配置的 gameDir |

官方启动器默认实际游戏目录通常是 .minecraft。PCL 启用版本隔离后通常是 .minecraft/versions/实例名。自定义游戏目录应以启动器设置为准。

“版本文件夹里有 26.3”不代表把模组放进这个文件夹的 mods 就一定生效。检测程序允许分别选择版本目录与实际游戏目录。

### 4.4 安装桥接与前置

1. 打开这个实例实际使用的游戏目录。
2. 解压“Minecraft_桥接与前置.zip”到该目录。
3. mods 中应有 skycraft-0.1.2.jar 与 fabric-api-0.161.0+26.3.jar。
4. 同一个模组只保留一个版本。不同时保留旧桥接 JAR，也不同时放多个 Fabric API。
5. 暂时不要添加额外模组，先用这两个必需 JAR 验证基础桥接。

JAR 不需要再解压。不把它放入 resourcepacks、plugins、城堡的 BepInEx/plugins 或启动器 libraries。

### 4.5 模组界面看不到模组

先检查加载器和实际 mods 路径。Fabric 模组一般包含 fabric.mod.json；NeoForge 模组一般包含 META-INF/neoforge.mods.toml。改文件名或改版本号不能把 NeoForge 模组转换为 Fabric。

本项目的 Re-Avaritia Fabric 26.3 移植仍未完成，没有可用成品 JAR。官方 NeoForge 26.3 JAR 不作为桥接前置安装。

## 5. Vulkan 图形 API 与 GPU 共享

### 5.1 推荐启用方法

1. 自行启动 Minecraft 26.3 实例。
2. 打开选项 → 视频设置，找到“图形 API / Graphics API”。整合包界面可能调整分类名称。
3. 选择 Prefer Vulkan / Vulkan 优先，应用设置。必要时正常退出并重新启动这个实例，使新后端生效。
4. 进入世界，按 F3 查看右侧显卡信息。真正启用时应出现 Vulkan 及其版本；出现 OpenGL 就仍在使用 OpenGL。
5. 选择框显示 Prefer Vulkan 只是偏好。驱动或扩展初始化失败时可能回退，不能仅凭设置宣布 Vulkan 已成功。

[Minecraft 26.3 官方说明](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-3)介绍了该版本的渲染更新。此教程使用的是 26.3 原生图形 API，不需要另外混装一个不匹配版本的 VulkanMod。

### 5.2 检测程序怎么看 Vulkan

程序只读 options.txt 中的 preferredGraphicsBackend 和最近日志。如果选项是 vulkan，会显示已选择 Vulkan 优先；default 代表自动模式，不能据此断言实际后端一定是 OpenGL。

最近日志出现 Vulkan GPU overlay ACTIVE，表示那次运行曾确认 D3D11 消费端收到共享画面。日志可能来自上一次运行，因此本次是否启用仍请查看 F3 和当次日志。

如果需要回到 OpenGL，使用同一个图形 API 设置切回并重启。不要删除资源包、整个存档或所有优化模组来切换后端。

### 5.3 引擎已启用不等于共享已启用

城堡端继续使用 D3D11。两边的共享需要合适的驱动、Windows 共享接口及同一显卡适配器。双显卡机器可在 Windows 图形设置中让两个游戏使用同一块独显。

Vulkan 不成功时，先查看当前日志、更新显卡厂商的正式驱动，再选择适合自己的后端。检测程序不会修改全局 Vulkan 驱动登记，不提供把其他电脑的 NVIDIA ICD 路径导入自己系统的脚本。

性能也取决于 CPU、后台帧率、分辨率、渲染距离与其他模组。两个游戏同时运行会共同消耗资源，不能以 Minecraft 的 FPS 直接代表城堡最终显示帧率。

## 6. 使用自动识别小程序

1. 保持 CastleCraft安装识别.exe、package-manifest.json 和教程文件夹在同一位置，不要只复制 EXE。
2. 双击程序，等待自动寻找 Steam 库和常见 .minecraft 位置。
3. 多个实例时选择你真正要玩的 26.3/Fabric 实例。自动发现不到可用“选择”按钮指定。
4. 确认“实际游戏目录”与启动器 gameDir 一致；Java 路径可选，但建议指定实际使用的 javaw.exe。
5. 点击“检查安装”。红色项目是待处理条件，绿色结果表示本包要求的文件与版本基准一致。
6. 识别通过后，程序提示你自行启动两个游戏。它没有启动、结束进程、安装模组、下载游戏、改注册表或写入游戏设置的按钮。

检测会解析真实版本 JSON 及继承关系，而不是靠目录名猜版本。若游戏脚本、桥接或加载器哈希不同，它会提示与本包基准不同。**已经使用另一份更新补丁时，不要为了让旧检测包通过而倒退版本；应更新整套教程包的清单和配套文件。**

可选命令行只读检查示例：

```
CastleCraft安装识别.exe --discover
CastleCraft安装识别.exe --check --castle "D:\Games\Lost Castle" --minecraft "D:\MC\.minecraft\versions\26.3-Fabric" --game-dir "D:\MC\.minecraft\versions\26.3-Fabric" --java "C:\Program Files\Java\jdk-25\bin\javaw.exe"
```

返回 0 表示安装检查通过，2 表示未通过。程序不会尝试运行 Java；Java 检查读取所选运行时的 release 文件。未选择 Java 时会明确提示实际运行时仍需用户核对。

## 7. 两个游戏的启动与操作

1. 用户自行从 Steam 启动 Lost Castle。进入可游玩的大厅或场景，让城堡端插件加载。
2. 用户自行在 Minecraft 启动器选择已安装的 26.3/Fabric 实例启动。
3. 桥接连接后会使用专用 Minecraft 镜像世界。首次创建或打开需要等待；不要为了处理加载延迟去删除自己的正常存档。
4. 回到城堡窗口，按 F8 切换 Minecraft 角色接管。正常加载和传送确认期间会暂时等待。
5. 按 F5 切换视角；按游戏下方提示使用当前解析到的装备切换键。

| 操作 | 本版用途 |
| --- | --- |
| F8 | 原生城堡角色／Minecraft 角色接管切换 |
| F5 | 视角切换 |
| 鼠标、WASD、数字、滚轮 | 原生 Minecraft 控制与物品栏；具体键位仍以自己的设置为准 |
| 解析后的武器切换键 | 默认候选为 F6，也可能因键位冲突解析为 F7 等；以屏幕提示为准 |
| Ctrl + 解析后的武器切换键 | 城堡装备接入／脱离 |
| 滚轮或数字选择原生物品 | 返回 Minecraft 武器/物品模式 |

不要把所有按键都当作固定 F7。默认配置和冲突处理会决定最终键位，屏幕提示及 castlecraft.bridge.cfg 是当前实例的依据。

连接后 Minecraft 可能由桥接调整窗口显示方式。检测小程序不会隐藏窗口；小程序识别成功也不代表运行中的桥接已经接管。

## 8. 模组整理与可选安装

### 8.1 最小必需组合

城堡端：BepInEx 5.4.23.5 + CastleCraft.Passthrough.dll + CastleCraft.GpuBridge.dll。

Minecraft 端：Minecraft Java 26.3 + Java 25 + Fabric Loader + Fabric API + skycraft-0.1.2.jar。

这套最小组合用于首先确认基础加载。它不要求安装所有 RPG、生物、技能、建造或光影模组。

### 8.2 可选模组

参考随包的可选模组清单，从作者提供的来源自行下载与 26.3/Fabric 兼容的版本。建议使用单独实例逐个添加，避免重复 ID 或不同版本混装。额外模组不是基础桥接必需项。

### 8.3 资源包

资源包放入实际游戏目录的 resourcepacks，并在 Minecraft 内启用；不要放到 mods。建议先确认 Minecraft 自己能正常显示皮肤、物品和模型，再检查城堡桥接结果。

普通纹理、模型与所有 GPU 着色器特效不是同一种资源。任意模组的特殊着色器和粒子不自动保证全部导出；出现问题时记录具体物品/生物/特效和版本。

## 9. 常见问题与日志定位

| 现象 | 排查步骤 |
| --- | --- |
| 城堡识别不到 Minecraft | 检查两端是否启动了正确实例、城堡加载日志、mods 路径、F8 提示；不要另装旧桥接 |
| 模组搜索不到 | 检查平台与 mods 实际目录；NeoForge JAR 在 Fabric 中通常不会被加载 |
| 启动报 skycraft.client Mixin 错误 | 保留当次 crash-reports 和 latest.log，核对桥接包构建号与 26.3/Fabric 版本；不同补丁不能仅凭 0.1.2 文件名区分 |
| Prefer Vulkan 但 F3 是 OpenGL | 设置只代表偏好，查看 Vulkan 初始化失败及回退日志；检查驱动和实际启动实例 |
| 进门或 Boss 过场等待 | 传送、碰撞和剧情安全确认会影响接管；持续卡住请保留日志，不手动跳过 ACK 或删除房间记录 |
| 自定义皮肤消失 | 先在 Minecraft 自己的 F5 画面确认皮肤是否已加载，再区分账号网络/皮肤加载与桥接导出 |
| 物品白色、场景黑块或穿模 | 记录物品/场景、视角、资源包和模组组合；这些与后台 FPS、纹理或模型路径需要分别定位 |
| 动物远离却声音贴耳 | 本包含空间音频修补；人工观察方向/距离，仍有问题时记录具体生物和两端画面 |
| Crash Assistant 弹窗 | 查看该次日志。不要仅凭弹窗猜是版本不兼容；小程序本身不运行 Fabric/Minecraft 或该助手 |
| 小程序报文件不同 | 可能是旧包、更新补丁或路径选错；核对构建清单，不要盲目覆盖更新版本 |

日志位置：城堡为游戏目录/BepInEx/LogOutput.log；Minecraft 为实际游戏目录/logs/latest.log，崩溃报告为实际游戏目录/crash-reports。发送日志前自行检查是否含用户名、服务器地址或账号信息。

## 10. 更新、卸载与保存点

更新前正常退出两个游戏，备份旧桥接文件及配置。成对使用同一份构建清单里的 Host/Guest/GPU 桥接文件，不把未完成的开发构建混入已有稳定包。

卸载桥接时移走 CastleCraft 插件文件夹和 skycraft-0.1.2.jar。BepInEx 若仍供其他模组使用，应保留；Fabric API 若仍供其他 Fabric 模组使用，也应保留。不要把这些操作扩大为删除存档或整个 mods 文件夹。

本包是制作时的固定快照。完整建模、所有装备视觉、全部技能效果、骑乘/驯服等仍有独立未完成记录；此前用户确认流畅不代表这些全部完成。最近的空间音频修补有构建和 Mixin 检查，实际效果继续由用户验收。

## Vulkan 显示扩展和一键安装入口

打开检测程序的“Vulkan / 驱动助手”。它读取每张显卡的 Windows 驱动版本、日期，调用系统 Vulkan Loader 检查 VK_KHR_surface 和 VK_KHR_win32_surface，并实际创建 Vulkan 实例和隐藏 Win32 Surface，列出可见 Vulkan 显卡及 API 版本。检测不会启动游戏，也不修改系统。

扩展存在不等于 Minecraft 已启用 Vulkan；检测通过后仍应在游戏 F3 中确认 Vulkan。该检查不替代交换链呈现或 GPU 共享验收。检测失败也可能由 Loader 搜索、驱动登记或多显卡环境导致，不能直接断言硬件不支持。

缺失时按显卡品牌点击官方安装助手按钮：

- [NVIDIA App](https://www.nvidia.com/en-us/software/nvidia-app/)：官方页面下载，进入 Drivers 下载并安装匹配驱动。
- [AMD 自动检测安装](https://www.amd.com/en/resources/support-articles/faqs/GPU-Driver-Autodetect.html)：官方工具识别支持的显卡与系统并下载驱动。
- [Intel 驱动助手](https://www.intel.com/content/www/us/en/support/detect.html)：官方工具扫描支持的设备，按提示更新。

完成官方下载后，点击“运行已下载的官方安装器”，选择 EXE。程序先校验 Authenticode 签名有效且签发给 NVIDIA、AMD 或 Intel，然后请求 Windows 管理员权限启动官方安装向导。它不会静默替换驱动，不绑定某台电脑的驱动版本，不自行写 Vulkan 注册表。笔记本或旧显卡若不被助手支持，应按官方提示使用整机厂商或对应产品驱动。

安装完成按厂商提示重启，再点“重新检测”。VK_KHR_surface 是驱动/Loader 暴露的能力，不是一个可独立下载的扩展文件。不要用来源不明的 vulkan-1.dll 覆盖系统文件。CLI 参数 --vulkan 也可输出只读检测结果。
