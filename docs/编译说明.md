# 从源码编译

源码只含模组和桥接代码；游戏引用库须从自己的安装中取得。

## 城堡端

需要 .NET SDK 8 或兼容 SDK。为了匹配项目中的相对引用，将本仓库文件夹命名为 CastleCraft，放在 Lost_Castle.exe 同级目录。游戏目录应已有 Lost_Castle_Data/Managed 和 BepInEx/core。

```powershell
dotnet build src/passthrough/CastleCraft.Passthrough.csproj -c Release
dotnet run --project tests/host/CastleCraft.HostTests.csproj -c Release
```

产物：src/passthrough/bin/Release/netstandard2.1/CastleCraft.Passthrough.dll。不要上传游戏 Managed DLL。

## Minecraft 端

需要 64 位 JDK 25。设置 JAVA_HOME 指向自己的 JDK，在 src/guest 中运行：

```powershell
.\gradlew.bat build --no-daemon --console plain
```

产物：src/guest/build/libs/skycraft-0.1.2.jar。Gradle 首次运行会下载构建依赖，需要联网。主源码来自当前发布快照，构建工具的依赖版本以 gradle.properties 为准。

## 原生 GPU 桥接

需要支持 Windows x64 的 MinGW-w64 g++ 和 Windows SDK 对应头文件/库。直接编译 src/native-gpu/Bridge.cpp，链接 d3d11、dxgi、opengl32、uuid、winpthread；完整参数见 src/native-gpu/build.py。该脚本中的 compiler 路径需要改成自己的 g++。先创建 build 目录。

生成 CastleCraft.GpuBridge.dll 后，除城堡插件目录外，也要复制到 src/guest/src/client/resources/native/windows，再构建 Guest JAR，保证两端原生库一致。

## 安装检测程序

源码在 tools/doctor。使用 Windows .NET Framework 4.8 的 csc，编译 CastleCraftDoctor.cs 和 VulkanDoctor.cs，目标 winexe/x64，引用 System.Windows.Forms、System.Drawing、System.Web.Extensions、System.Core、System.IO.Compression、System.IO.Compression.FileSystem、System.Management。package-manifest.json 须与程序同目录。

## 模型定义

src/first-person-models 保留原创方块模型定义；src/passthrough/GeneratedCastleCuboids.cs 为已生成代码，可直接参与编译。重新生成时使用 tools/compile_cuboid_models.py，按脚本调整项目根路径。原游戏纹理运行时从本机读取，不随仓库分发。

本仓库不打包本地缓存、游戏库、账号或存档。重新编译不等于已经完成实机验收。
